# Dependency Upgrades Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `/home/alim/storefront` to the newest dependencies its Next.js/ESLint toolchain supports, with no behavior change and all checks green.

**Architecture:** Pure version bump in `package.json`, regenerated `package-lock.json`, then verification by build, typecheck, lint, and a production smoke test. No product code should change; any code edit exists only to satisfy a bump-induced break.

**Tech Stack:** Next.js 16 (App Router), React 19, Tailwind CSS 4, TypeScript 5.9, ESLint 9, npm.

**Spec:** `docs/superpowers/specs/2026-11-09-dependency-upgrades-design.md`

## Global Constraints

- Stay on `typescript` 5.9.3 and `eslint` 9.39.5. Do not bump either major.
- Never use `--legacy-peer-deps`, `--force`, or `--omit=peer`. If npm reports `ERESOLVE`, stop and report.
- Do not modify or commit `components/admin/ProductPhotoManager.tsx` or `components/home/BrandLogo.tsx` (pre-existing local edits).
- Target versions exactly: next 16.4.5, react/react-dom 19.3.1, lucide-react 1.70.0, tailwindcss 4.3.5, @tailwindcss/turbopack 4.3.5, eslint-config-next 16.4.5, @next/eslint-plugin-next 16.4.5, @types/node 24.19.2.
- Work on branch `chore/deps-2026-11`. No changes to `main`.
- For Next.js behavior questions, `node_modules/next/dist/docs/` is authoritative (`AGENTS.md`). Context7 only for non-Next packages, pinned to the installed version.

## Review Focus

- lucide-react icons removed or renamed between 1.59.0 and 1.70.0 — imports must fail the build, not render blank (Task 1, build step).
- React 19.3.1 type changes — props/refs that typechecked before must still typecheck (Task 1, tsc step).
- Next 16.4.5 patch — production build and server start must both work (Tasks 1 and 2).
- @types/node 24 vs the Node 24 runtime — typecheck must not reference APIs absent at runtime (Task 1, tsc step).
- Updated `eslint-config-next` with the existing flat config — lint must pass without config edits (Task 1, lint step).
- Runtime-only regressions that a build cannot catch (API routes, env handling) — the app must boot under `next start` (Task 2).

### Task 1: Bump dependencies and verify the build

**Files:**
- Modify: `package.json`
- Modify: `package-lock.json` (generated by npm)

**Interfaces:**
- Consumes: current `package.json` dependency ranges.
- Produces: a lockfile resolving next 16.4.5, react/react-dom 19.3.1, lucide-react 1.70.0, tailwindcss 4.3.5, @tailwindcss/turbopack 4.3.5, eslint-config-next 16.4.5, @next/eslint-plugin-next 16.4.5, @types/node 24.19.2; typescript stays 5.9.3 and eslint stays 9.39.5.

- [ ] **Step 1: Capture a baseline**

Run each in `/home/alim/storefront`:

```bash
npm run build
npx tsc --noEmit
npm run lint
```

Expected: all exit 0. If any fails, stop and report the failure — it predates the bump and must be fixed or waived before continuing.

- [ ] **Step 2: Update `package.json` ranges**

Set these entries (keep the `^` style already used for the minor-range packages):

```json
"dependencies": {
  "clsx": "^2.1.1",
  "lucide-react": "^1.70.0",
  "next": "16.4.5",
  "react": "19.3.1",
  "react-dom": "19.3.1",
  "tailwind-merge": "^3.7.0"
},
"devDependencies": {
  "@next/eslint-plugin-next": "^16.4.5",
  "@tailwindcss/turbopack": "^4.3.5",
  "@types/node": "^24.19.2",
  "@types/react": "^19",
  "@types/react-dom": "^19",
  "eslint": "^9",
  "eslint-config-next": "^16.4.5",
  "tailwindcss": "^4.3.5",
  "typescript": "^5"
}
```

- [ ] **Step 3: Install**

Run: `npm install`

Expected: exits 0, no `ERESOLVE` or peer-dependency warnings. `package-lock.json` changes.

- [ ] **Step 4: Confirm the resolved tree**

Run: `npm ls next react react-dom lucide-react tailwindcss typescript eslint @types/node --depth=0`

Expected: the target versions above; `typescript@5.9.3`; `eslint@9.39.5`; no `invalid` or `extraneous` markers.

- [ ] **Step 5: Fix bump-induced fallout, if any**

Run `npm run build` first. If it fails on a lucide import such as `export 'X' was not found in 'lucide-react'`, replace that import with the current icon name from `node_modules/lucide-react` exports and re-run. If types change, fix at the call site — do not add `any` or `@ts-ignore`. If Next.js API behavior is involved, read the matching guide under `node_modules/next/dist/docs/`. If a fix needs more than a local rename or type adjustment, stop and report.

- [ ] **Step 6: Build passes**

Run: `npm run build`

Expected: production build completes, routes compiled for `/`, `/products`, `/categories`, `/categories/[slug]`, `/image-credits`, `/admin/products`.

- [ ] **Step 7: Typecheck passes**

Run: `npx tsc --noEmit`

Expected: no output, exit 0.

- [ ] **Step 8: Lint passes**

Run: `npm run lint`

Expected: exit 0, no errors.

- [ ] **Step 9: Commit**

```bash
git add package.json package-lock.json
git commit -m "chore: bump dependencies to latest compatible versions"
```

Do not stage the two pre-existing modified component files or the design doc.

### Task 2: Production smoke test

**Files:**
- Test only; no file changes expected.

**Interfaces:**
- Consumes: the build output and lockfile from Task 1.
- Produces: verified running app on the bumped dependencies.

- [ ] **Step 1: Start the production server**

Run in the background from `/home/alim/storefront`: `PORT=3100 npm start`

Expected: `next start` reports ready and listening on port 3100.

- [ ] **Step 2: Load the home page**

Navigate the Playwright browser to `http://localhost:3100/`.

Expected: the storefront home renders (site header, hero/content, product or category links); no browser console errors.

- [ ] **Step 3: Load a category page**

Navigate to `http://localhost:3100/categories/marine-engines`.

Expected: the category landing page renders with its product list; no browser console errors.

- [ ] **Step 4: Stop the server and close the browser**

Close the Playwright browser and terminate the `next start` process.

- [ ] **Step 5: Fix or report**

If a page fails only because of the bump, make the minimal fix and commit it (message: `fix: <what broke> after dependency bump`). If it fails for a reason unrelated to the bump, stop and report with the observed error.
